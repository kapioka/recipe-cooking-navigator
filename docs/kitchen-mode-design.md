## 2. 情報と操作の配置

- アプリの通常ホームはRecipe一覧のまま。文字付きの「キッチンツールを開く」ボタンから明示的に入る。通常のRecipe閲覧では常時点灯を有効にしない。
- 最上部に「キッチン」、24時間表記の現在時刻、右端に「終了」。現在時刻と残時間はラベル・位置で区別する。時刻を1秒ごとにTalkBackへ読み上げない。
- 続いて「タイマー」「追加」と、名前・残時間・状態・操作を持つ行を並べる。色だけで状態を示さない。名前は折り返せる。
- 初期UIは最大2行を常設し、3件以上は「すべてのタイマー（件数）」から一覧へ入る。終了未確認を優先し、次に実行中の期限順。同じ状態内で残時間更新だけを理由に行を入れ替えない。全タイマーは保持し、表示件数でデータを制限しない。
- タイマー0件では「タイマーはまだありません」「追加」。開始していない時間をカウントダウン表示しない。
- 下部は基本画面、Recipe一覧、Recipe詳細、Cooking modeを切り替える。タイマー管理の所有者はこの子画面に置かない。
- 基本画面に「レシピを開く」。一覧・検索・取込・詳細の既存導線を維持する。詳細では選択人数と開始操作、Cooking modeでは同じCookingContextの材料・手順を表示する。
- Cooking modeの下部は「材料を見る｜工程一覧」「読み上げ」「前へ｜操作方法｜次へ」を固定。右上の音声操作ON/OFFは独立させる。工程の推奨タイマー開始は上部「追加」または工程の時間から到達できるようにし、機能を失わない。
- タイマー領域・固定ボタン・シートは左右タップとスワイプによる工程送りの対象外。本文の30%・40%・30%操作、縦スクロール、TalkBack時の明示ボタンを維持する。
- 末尾で「次へ」は無効。調理完了とキッチン終了は別操作。「調理を完了」はRecipe側のメニューに置き、Session保存成功後だけ完了扱いにする。

## 3. 画面サイズと文字拡大

基準モックは390×844の縦向き。配色は現行の暖色背景・rust色・日本語sans-serifを継承し、操作領域は最低48dp、本文は18sp以上を基準とする。

| 条件 | 配置 |
|---|---|
| 通常の縦向きスマートフォン | ヘッダー＋タイマー最大2行、独立スクロール本文、固定操作デッキ |
| 幅720dp以上の横向き・タブレット | ヘッダーは全幅。左に時計・タイマー約30〜35%、右にRecipe本文とその下の操作デッキ |
| 短い画面・文字拡大で本文の高さが200dp未満 | 時計を残し、タイマーを終了未確認件数・最短残時間・全一覧へのボタンに集約。下部操作は最低限の前へ・操作・次へを固定し、材料・読み上げ等へ操作シートから到達できる |

文字を縮小して押し込めない。全一覧と操作シート自体もスクロール可能とする。完了判断や食品安全情報を省略せず、本文全文へ到達できることを受入条件にする。画面回転はOSに任せ、アプリから回転設定を変更しない。

## 4. Kitchenの状態遷移

Kitchenが開いているか、foregroundか、どのRecipe画面か、タイマーが実行中かを独立させる。

| 操作・イベント | 結果 | 常時点灯 |
|---|---|---|
| 通常ホームでキッチンを開く | 基本画面へ入る。タイマーを勝手に開始しない | foregroundの間だけON |
| Recipe一覧・詳細へ移動 | 同じKitchen内で内容だけ切替。タイマー期限は不変 | ON |
| 調理開始・続きから | 保存成功後にCooking modeへ。既存CookingContextを適用 | ON |
| ホームへ退避・ロック・Activity非表示 | Kitchenはsuspended。TTSと認識を停止。タイマーは画面から独立 | OFF |
| 同じプロセスでforeground復帰 | 時刻と期限を再評価。音声認識を無断で再開しない | Kitchenが有効ならON |
| Recipeを中断・閉じる | 途中位置を保持し基本画面へ。Recipeタイマーも自動停止しない | Kitchen内なのでON |
| 別Recipeを閲覧 | 現在の調理位置を保持して閲覧。明示的に中断・開始するまでは実調理対象を切り替えない | ON |
| タイマー期限到達 | finishedにし、終了表示。工程・Sessionを自動確定しない | Kitchenの状態に従う |
| キッチンの「終了」・ルートで戻る | 下記の終了フローを通し通常ホームへ | OFF |
| プロセス再生成・異常終了後の起動 | 通常ホームから開始。復元タイマーを案内するが、Kitchen・TTS・音声を自動開始しない | OFF |

終了時、動作中タイマーがなければ直ちに終了。動作中なら「タイマーを続けて終了」「停止して終了」「戻る」を提示する。続行はbackground通知・復元を検証済みのPhase 4以降だけ提供する。Phase 3では「停止して終了」「戻る」とし、継続を保証するような表示をしない。停止状態の保存に失敗した場合は終了成功を表示せず、ユーザーが戻れる状態を保つ。

常時点灯はKitchenのforeground所有者が一元管理する。子画面のdisposeだけで解除しない。Activity非表示・終了・例外経路では必ず解除する。通常のCooking modeだけを使う現行実装の点灯契約は、Kitchen実装への移行までは変更しない。

## 5. タイマーの意味と操作

| 状態 | 表示と操作 | 遷移 |
|---|---|---|
| ready | 設定時間、「開始」「リセット」 | 明示開始でrunning。リセットは未開始タイマーを閉じて00:00へ戻し、時間を選び直す |
| running | 期限から計算した残時間、「一時停止」 | pauseでpaused、期限到達でfinished |
| paused | 保持した残時間、「再開」 | resumeで新しい期限を設定、リセットでready |
| finished | 「終了」「音を止める」 | 確認後は「終了・確認済み」を保持し、再設定または一覧から閉じる |
| cancelled | 停止済み。後から通知しない | 明示的な再設定がなければ再起動しない |

「停止」は今回の計測を中止、「一時停止」は残時間を保持する操作として区別する。終了音を止めても工程完了やRecipe完了にはしない。延長・再設定・取消ごとに通知世代を更新し、古い期限の通知を無効化する。複数の同時終了はタイマー名ごとの表示と集約した終了音で知らせる。

タイマー作成シートでは名前・分・秒を設定し、明示「開始」で起動する。0秒や不正値を開始しない。人数変更で時間を倍率変更しない。Recipeから作る場合は料理名・工程名を初期名にする。Recipeを閉じた後も名前と期限を保持する。

音声の「タイマー開始」は従来どおり現在工程の推奨時間を対象とする。停止・残り時間は現在工程に対応する一意な実行中タイマー、なければ唯一の実行中タイマーを対象にする。複数候補なら名前で選べる画面を開き、推測で別のタイマーを停止しない。

## 6. 通知と復元の境界

- foregroundの終了表示、OS通知、音、振動は同じ終了イベントから処理する。foregroundとbackgroundの双方で二重に音を鳴らさない。
- 終了音は現在工程のTTSより優先する。TTSと音声認識を停止して終了を知らせ、勝手にTTSや認識を再開しない。「音を止める」は通知からも可能にする。
- 通知タップでは対象タイマーを示す。Kitchen modeへの明示的な入口として扱い、Recipeの工程は移動しない。
- 通知権限は初めてbackground終了通知を使う時に説明する。権限拒否・チャネル無効は「画面を閉じると終了を通知できません」と表示し、画面内タイマーは使えるようにする。
- 音量0・サイレント・電池制限・強制停止時の通知制約を案内し、鳴動や定刻配送を未確認のまま保証しない。端末設定を自動変更しない。
- 同じ起動中は単調時計を使い、端末時刻変更で残時間が急変しない設計とする。OS時計・alarmの具体的なAPIと権限要件はPhase 4着手時に公式資料・実機で確定する。
- 通常のアプリプロセス再生成後は保存済み期限・状態を復元する。期限超過はfinishedとして一度だけ通知・表示する。壊れた保存を空データ扱いで上書きしない。
- 初版の端末再起動後は通知の自動再予約を非対応とする。再起動を識別し、実行中だったタイマーは要確認として保持。「端末再起動のためタイマーを確認してください」と案内し、古い時刻から黙って再始動しない。

## 7. Phase別の実装範囲

| Phase | 実装すること | まだ完成扱いにしないこと |
|---|---|---|
| 3 | KitchenSession・共通タイマーcontroller/store、時計、単独タイマー1件の基本操作、Kitchen内で一覧・詳細を閲覧、foreground点灯 | 複数操作UI、background終了通知、プロセス復元、Recipe工程との共通タイマー接続 |
| 4 | 複数タイマー、永続化・期限復元、通知・音・振動・世代管理、終了時続行 | Recipe由来タイマーと工程音声の統合 |
| 5 | Recipeタイマー、人数・再開・音声・TTSの統合、選択画像のCooking mode、既存タイマー状態の除去 | 実料理・長時間点灯の安定性評価 |

Phase 3でも配列と任意の作成元を持つモデルにし、1件表示を保存形式へ埋め込まない。Phase 5までは既存Cooking modeを通常経路で維持し、新旧タイマーを同時に使わせる導線を追加しない。Kitchen内から調理を始める統合動作はPhase 5で接続する。

## 8. 受入条件

| 自動検証 | 合格条件 |
|---|---|
| domain | 開始・pause・resume・延長・取消・終了が決定的。表示tickの回数で期限が変わらない |
| store | 複数ID、通知世代、保存失敗、破損・backup、未知versionを検証。RecipeとCookingContextの原本は不変 |
| 時刻 | 同一起動の壁時計変更、プロセス再生成、再起動識別、期限超過を注入時計で検証 |
| navigation | 0 Recipe・0 timerでも開始。画面切替と人数変更で既存タイマー不変。中断とKitchen終了を区別 |
| widgets | 390×844、844×390、834×1194、文字倍率1.0/1.3/2.0で主要操作と安全情報へ到達可能 |
| 操作競合 | timerボタン・縦スクロール・シート操作で工程が移動しない。最終工程の次へ無効 |
| 終了 | 消音してもfinished表示を保持。通知重複なし。自動工程移動・自動Session保存なし |

| 実機検証 | 合格条件 |
|---|---|
| 点灯と回転 | 開始・閲覧・中断・background・復帰・終了で点灯責務が一致。accelerometer_rotationとuser_rotationが前中後で不変 |
| 通知 | ロック、background、通常プロセス再生成、通知拒否、チャネル無効、音量0、同時終了、延長後の旧通知を確認 |
| 音声 | TTS・終了音・認識が競合せず、雑音下で他タイマーを誤停止しない |
| アクセシビリティ | TalkBackでタイマー名・状態・対象操作が分かる。毎秒の読み上げやフォーカス移動なし |

静的モックをこれらの合格証拠にしない。Phase 6の実料理・長時間点灯・電池・発熱の検証は別途残す。
