# 評価からの改善生成・通信量の修正 — 2026-10-13

## 確認できた原因

0.2.0のPixel 10aでGPT-6.1-Solによる改善依頼が97秒後に条件画面へ戻った。診断詳細は「AIへの送信・回答の受信: PoC応答の上限を超えました」。SSEの全行を合算する旧上限（1,048,576文字）が本体にも残り、完成前に停止していた。完成したRecipe本文が1MBを超えたと確認したものではない。

評価画面の改善希望は選択Feedbackの`revision_request.goal`として送信されていた。次の画面の「その他の希望」は別の追加欄で、元の希望を表示していなかった。

## 修正

- 選択Feedbackの改善希望を画面に表示し、追加入力欄を「追加の希望（任意）」にする。選択した評価・改善元・ID・次revisionは保持する。
- Recipe Schemaと新規生成の構造例は、JSONの空白を除き意味を変えず添付する。連携仕様は正本の生成・改善責務（6〜9節）を使い、Drive等の無関係な説明を除く。改善時は送信前に検証したFeedbackと改善元snapshotを維持し、Feedback Schemaと別の料理の構造例を重ねて添付しない。必要な仕様区間が見つからない場合は停止する。
- 出力はコンパクトJSONを依頼する。材料・分量・食品安全上の判断や必須Schema項目は省略しない。参照例の改善依頼では添付指示が27,263文字から9,924文字になった。全文書添付を合算した旧比較値との比較であり、全レシピで同じ通信量や速度を保証しない。
- 受信通知全体は16,777,216文字、回答本文は1,048,576文字で別に制限する。無制限にはしない。途中の本文だけでは成功とせず、検証済み`response.completed`を受け取った時点で返す。接続終了待ちによる余計な待機をなくす。
- 時間切れを形式エラーへ丸めず分類し、受信上限・時間切れは条件画面に理由を表示する。使用モデルも表示する。完了時は診断詳細でRecipe本文の文字数を確認できる。
- 送信バイト数・受信通知の文字数・本文の文字数だけを診断logへ出す。本文・希望・アカウント・tokenは出さない。自動再送、モデルの自動変更、APIキーへの切替は行わない。

## 機械検証

本体248 tests、共通SIWCの26 tests、analyze、formatterが成功。1MBを超える通知と小さな本文、本文と通知の各上限、完了後も開いている通信、未完了と時間切れ、表示した希望と送信Feedbackの一致、追加希望、保存状態の保持を確認した。

公式のModels and inferenceを2026-10-12に再確認し、`store=false`、`stream=true`、公開Responses、`response.completed`までの完了判定を維持した。ZIP等の圧縮データをモデルへ渡す方式や未確認のAPIパラメータは追加しない。

## 実機確認

Pixel 10aへ既存版と同じ証明書の正式署名APKを`adb install -r`で更新し、インストール後のAPK checksumが一致することを確認した。

所有する検証用レシピのVersion 3から「Reduce salt a little.」を改善希望として指定した。次画面の「評価から引き継いだ改善の希望」に表示され、使用モデルがGPT-6.1-Solであることを確認して送信した。約75.4秒で回答の完了を受信し、Schema・改善元・次revisionの検証を通って内容確認画面へ進んだ。生成候補は保存していない。

- 実際の送信HTTP JSON: 26,590 bytes
- 受信したSSE通知全体: 655,024文字
- 完成したRecipe本文: 5,161文字

この1回では受信と内容確認が成功したが、モデルの応答時間やすべてのレシピでの成功を保証する結果ではない。端末の自動回転設定・固定方向は更新前後とも0 / 0だった。

追加の指定に合わせ、評価画面の「選択した評価でChatGPTに改善を依頼」を共通テーマの濃い緑のFilledButton、「Feedbackを共有」をOutlinedButtonに変更した。既存widget tests 24件が成功した。
