# 調理モードのUI設計

2026-09-05のユーザー依頼に基づき、会話「レシピUI操作方法」の提案を製品仕様へ整理した設計。アプリへの実装完了を示す文書ではない。製品上の優先順位は[product-spec.md](product-spec.md)、保存責務は[data-model.md](data-model.md)、実装状況は[roadmap.md](roadmap.md)を正本とする。

## 読むモードと作るモード

通常のレシピ詳細は縦スクロールで、材料、全体工程、器具、事前準備、使用Versionを確認する。「調理開始」でCooking modeへ入り、今行う1工程を大きく表示する。開始したRecipe IDとrevisionは調理中に固定し、新Revisionの取り込みやactive変更で途中の内容を差し替えない。

## MVPに採用する操作

| 操作 | 動作 |
|---|---|
| 本文領域の左30%をタップ | 前工程 |
| 本文領域の中央40%をタップ | 操作UIの表示・非表示 |
| 本文領域の右30%をタップ | 次工程 |
| 左へスワイプ | 次工程 |
| 右へスワイプ | 前工程 |
| 上下へスクロール | 現在工程の長い本文を読む |
| 操作UIの「工程一覧」 | 全体工程を開き、選択した工程へ移動 |
| 操作UIの「材料」 | 材料一覧を開き、閉じると元の工程へ戻る |

左右方向は横書きの前・次に統一する。30%・40%・30%は本文の操作対象幅を基準とし、OSのシステム操作領域、ボタン、スクロールバー、開いているパネルを除外する。境界線は常時描画せず、初回の簡単な操作案内と再表示できるヘルプを用意する。

一度の指操作で1工程だけ移動する。スワイプ終了をタップとして二重処理しない。縦スクロール中やパネル・ボタンの操作では工程送りを発生させない。先頭では前へ進めず、末尾の次操作だけで調理完了や評価保存を確定しない。「調理を完了」の明示操作で終了する。

TalkBack利用時は明示的な前へ・次へ・操作UIボタンに到達できるようにし、画面全体の独自スワイプで読み上げ操作を奪わない。ジェスチャーの距離・速度閾値と最終的な配置は実装時にPixelで検証する。

## 情報配置と操作UI

通常は操作バーを隠し、工程を読む領域を広くする。中央タップで操作バーを出し、もう一度中央タップで閉じる。UIの開閉だけでは工程・タイマー・音声ON/OFFを変更しない。

常時確認できる情報:

- 料理名と現在位置（例: `3 / 8工程`）
- 工程名、本文、使用材料名とその工程で使う分量
- 火加減、時間、完了判断、安全上の注意（データがある場合）
- 音声操作状態、実行中タイマーの残時間と終了通知

操作UIから材料、全体工程、タイマー、音声ON/OFF、現在工程の読み上げ、前へ・次へ、調理モード終了へ到達できる。本文が長くても情報を切り捨てず、縦スクロールで全文を確認できるようにする。

## 工程一覧と完了状態

工程一覧は工程番号・短い工程名・現在位置を示し、任意工程へ移動できる。一覧を閉じるだけなら元の工程へ戻す。選択して移動した場合は新しい現在位置を保存する。

ページ送りや一覧ジャンプを、食品の加熱完了や作業完了の判定に使わない。完了工程をチェック・淡色表示する拡張は、ユーザーの明示的な完了操作と保存方法を定義してから追加する。初期版は現在位置と閲覧位置だけを扱い、ジャンプで飛ばした工程に完了マークを付けない。

## 途中位置の自動保存と再開

現在工程が変わった時点で、Recipe ID・revision・Step IDをローカルの調理進行状態へ保存する。アプリ終了時だけの保存に依存しない。保存失敗は知らせ、未保存の位置を「保存済み」と表示しない。

レシピ詳細に「調理途中です」「工程 4 / 6」「工程名」と「続きから」「最初から」を表示する。「続きから」は保存した同じrevisionとStepを開く。「最初から」は確認後、新しい進行状態として先頭へ戻す。過去のRecipe revision、Cook Session、Evaluationは削除しない。

参照先revision・Stepが存在しない、または保存データが壊れている場合は、latestや別工程へ推測で置き換えず、理由を表示してユーザーに開始方法を選んでもらう。再開だけでタイマーを新規起動したり、経過時間から工程を完了にしたりしない。実行中タイマーの中断・復元は別のタイマー状態管理として設計し、位置保存だけで継続を保証しない。

## 追加候補として保存する仕様

次の案は会話にあった拡張候補として残し、今回のMVP必須項目へ一括昇格させない。

- 調理ロック: 左右タップを残し、スワイプ・ピンチ・不要な操作を抑制する任意モード。中央タップによる解除導線、音声操作、タイマー停止、終了操作は利用可能にする。長文や安全情報がスクロールなしでは読めない場合はロックを許可しない。具体的な無効化範囲は実機検証後に確定する。
- 材料タップ・長押し: 分量詳細。既存の材料・分量再掲を置き換えない。
- 時間タップ・長押し: 明示的なタイマー開始ボタンを表示する。表示や長押しだけでは自動開始しない。
- 人数変更、容量・重量換算、温度換算: 元データを保持し、換算根拠と対応単位を定義してから追加する。容量から重量は食材依存なので一律換算しない。会話中の換算例は製品の換算表として採用しない。
- 材料チェック、工程内の自分用メモ・ハイライト。
- 任意写真・図のダブルタップ／ピンチ拡大。
- 文字サイズ、白・黒・セピアなどの表示テーマ、片手モード。
- 音量ボタン等の物理ボタンによる工程送り。音量調整との競合を解決してから採否を決める。

音声読み上げはこの候補群に降格させず、既存仕様どおり音声操作とともにMVP必須とする。写真・人数換算などでRecipe Schema変更が必要になった場合は、互換性・migration・examplesへの影響を別タスクで確認する。

## 受け入れ条件

1. 通常詳細は縦スクロールで読め、「調理開始」から1工程表示へ移れる。
2. 左30%／中央40%／右30%のタップと左右スワイプが上記の動作に一致する。
3. 縦スクロール、ボタン操作、パネル操作では工程が誤って移動しない。一度のジェスチャーで二重遷移しない。
4. 操作UI非表示でも材料・分量、完了判断、安全情報、現在位置、音声状態、実行中タイマーを確認できる。
5. 工程一覧から任意工程へ移動でき、飛ばした工程が完了扱いにならない。先頭・末尾で範囲外へ移動しない。
6. 再起動後に同じRecipe revision・Stepから再開でき、新Revisionの取り込みに影響されない。欠損や保存失敗を推測補完しない。
7. 「最初から」でも過去Revision・Cook Session・Evaluationを失わない。
8. タイマーは明示操作でのみ開始し、終了しても工程が自動移動しない。再開だけで新規起動しない。
9. Cooking mode終了で画面常時点灯を解除し、音声操作・TTSの既存必須条件を満たす。
10. Pixelで長文、文字拡大、TalkBack、中央UIの開閉、戻る操作、途中再開を検証する。
